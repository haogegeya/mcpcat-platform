# MCPCat Data Skill

MCPCat 是一个 MCP 聚合网关，一个端点提供餐饮下单与多领域实时数据查询工具。

## 使用前提

- 用户需先在 mcpcat.cn 注册账号并在控制台生成 API Key，通过本连接器的凭证表单填入。
- 连接后请优先调用 `tools/list` 获取当前账号可用工具（工具集随账号配置变化，本技能不预设数量），再按返回的 schema 调用。
- 麦当劳（mcd.*）与瑞幸（lkcoffee.*）工具需要用户已在对应品牌侧完成账号授权；若上游返回未授权错误，引导用户按提示完成授权后重试，不得代用户臆造登录态。

## 能力类别

| 类别 | 典型能力 | 说明 |
| --- | --- | --- |
| 麦当劳点餐 | 附近门店/得来速查询、餐品与套餐详情、创建订单（到店/外送/团餐）、历史订单、优惠券领取、营养成分 | 下单前必须走门店→餐品→订单预览链路 |
| 瑞幸咖啡 | 门店查询、商品搜索/切换、订单预览（previewOrder）、创建订单（createOrder）、订单状态与取餐码 | 先 preview 再 create |
| 天气 | 城市/区域信息、多日预报、空气质量 | 只读查询 |
| 物流 | 快递单号轨迹、公司自动识别 | 只读查询 |
| 金融生活数据 | 汇率、油价、贵金属、彩票开奖 | 只读查询，仅供参考 |
| 网络与出行 | DNS 解析、HTTP 状态、余票时刻、节假日 | 只读查询 |

具体工具名与参数以 `tools/list` 的 schema 为准。

## 下单安全规则（必须遵守）

1. **先预览、后确认、再下单**：任何 create-order / createOrder 调用前，必须向用户完整展示门店、商品、数量、金额、取餐/配送方式，并获得用户明确确认；禁止未经确认直接创建订单。
2. 支付由用户在品牌官方渠道（App/微信）自行完成，本工具只负责创建订单与查询状态；不得承诺自动支付。
3. 用户说"取消订单"时调用对应取消工具，取消前复述订单号确认。
4. 外送场景需用户明确提供或选择配送地址，不得复用历史地址而不告知。
5. 涉及手机号、地址等个人输入仅用于当次下单，不得写入回复内容之外的位置。

## 错误处理

- 错误码 `-32001`（"API Key 无效或已停用"）：引导用户到 mcpcat.cn 控制台重新生成凭证并更新，不要重复重试。
- 上游品牌服务返回排队/限流：告知用户稍后重试，不得伪造下单成功。
- 查询类工具按次计费（以用户控制台展示为准），调用有明显成本时提前告知用户。

## 使用示例

用户："帮我在最近的麦当劳点份早餐，到店取。"
→ query-nearby-stores 选店 → 确认餐品与规格 → 展示订单预览（门店/商品/金额/取餐方式）→ 用户确认后 create-order → 返回订单号与支付入口提示。

用户："瑞幸来杯生椰拿铁。"
→ searchProductForMcp → previewOrder 展示价格与门店 → 用户确认后 createOrder → 告知取餐码查询方式。

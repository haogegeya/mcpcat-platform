# 计费（Billing）

> 规则以线上控制台显示为准。本文说明设计逻辑与判定口径。

---

## 货币：MCoin

| 项 | 规则 |
|----|------|
| 汇率 | **¥1 = 100 MCoin** |
| 新用户 | 注册送 **100 MCoin**（够把免费层 + 若干付费工具试一遍） |
| 充值 | 控制台充值档位带赠送 |
| 会员 | 会员提供**月度额度**，与钱包 MCoin 混合结算（先扣额度，再扣钱包） |

**为什么不用"元"直接计价**：单次调用成本是几分钱级别，用 MCoin 让"一次调用一个整数价格"成为可能，也让赠送、补贴、退款都能精确对齐。

## 单价

- 每个 Capability 有独立的 `sell_mcoin`（对用户售价）。
- 量级参考：**免费 / 3 / 5 MCoin** 居多——即 1 次常见查询约 ¥0.03～0.05。
- 免费工具不扣费、不进账单噪声。
- 具体某个工具多少钱，看 `tools/list` 返回或控制台工具市场卡片，本文不复制一份会过期的价目表。

## 成本防呆

平台侧每个 Adapter 有 `cost_mcoin`（上游采购成本），保存时校验：

- 收费工具（`sell > 0`）：**售价不得低于成本**——防止配置手滑把亏本价格上线。
- `sell = 0`：视为**免费补贴策略**，主动放行（用免费工具换留存和收录）。

## 失败自动退款

**这是平台最关键的一条承诺。**

```
调用 → 上游返回 → 判定结果有效性
                      ├─ 正常          → 扣费
                      ├─ 上游异常       → 退还
                      └─ 上游返回空结果 → 退还
```

- 判定由平台侧完成，**用户不需要提工单**，账单里直接可见退款流水。
- "空结果也算失败"是刻意的：Agent 拿到空数据等于没拿到数据，凭什么收费。
- 例外：**参数错误导致的上游拒绝**属于调用方问题，通常不退（所以参数约束必须写进 schema，见 [architecture.md](architecture.md#4-输入契约让模型能自己推导出正确调用)）。

## 结算链路

```
tools/call → 鉴权 → 五层限流 → 扣费预检 → 调上游 → 归一化 → 判定 → 扣 / 退 → 写 call_log
```

- **预检在调用上游之前**：余额不足直接返回，不产生上游成本。
  返回信息包含本次需要、钱包余额、会员额度剩余三个数字，用户不用猜。
- 每一笔 `tools/call` 都进 `call_logs`，控制台可按工具/时间/成败筛选。

## 订单生命周期

7 态状态机：

```
pending ──→ paid ──→ success
   │         └────→ failed
   ├──→ canceled（用户主动取消）
   └──→ expired（超 2 小时未付，定时任务自动关单）
```

- 超时关单：数据库扫描 + Redis 延迟队列双保险，每分钟执行。
- 用户取消会真正落库；若实际已支付，回查支付状态并提示到账，不吞钱。
- 已支付但到账失败：回滚标记保证幂等（`status IN ('pending','paid')` 条件更新）。

## 成本估算方法

给 Agent 上线前，先估量：

```
月成本 ≈ 日均调用次数 × 30 × 单次均价(MCoin) ÷ 100  （元）
```

示例：每天 2000 次查询、均价 3 MCoin → 2000×30×3÷100 = **¥1800/月**。
如果这个数不可接受，说明该场景应该走本地缓存或自建批量接口，而不是让 Agent 每次现问。

## 争议处理

账单异常、重复扣费、退款未到账 → 控制台「意见反馈」带订单号提交，或在[本仓库开 Issue](https://github.com/haogegeya/mcpcat-platform/issues)。
